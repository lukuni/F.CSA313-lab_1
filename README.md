## Юу хийсэн

Энэ репозитори нь [https://www.saucedemo.com](https://www.saucedemo.com) сайт дээр Playwright ашиглан 3 функционал тест бичсэн:

1. **Амжилттай нэвтрэх** → URL болон "Products" гарчиг харагдсаныг шалгах → logout хийж URL-ээ дахин шалгах
2. **Буруу нууц үгээр нэвтрэх** → "Epic sadface" алдааны мессеж гарсныг шалгах
3. **Нэвтэрсний дараа бараа сагслах** → сагсны badge-ийн тоо "1" болсныг шалгах → logout

Локатор болгонд `getByRole`, `getByPlaceholder`, `getByText` (`exact: true`), `getByTestId` зэрэг орчин үеийн, хэрэглэгчийн харагдацад тулгуурласан locator ашигласан бөгөөд XPath болон CSS id (`#react-burger-menu-btn` гэх мэт) ашиглаагүй. `playwright.config.ts` дээр `testIdAttribute: 'data-test'` тохируулж, saucedemo сайтын `data-test` атрибутыг `getByTestId()`-ээр уншсан.

## Ажиллуулах заавар

```bash
npm install
npx playwright install
npx playwright test
npx playwright show-report
```

Тест нь `chromium` дээр, `baseURL: https://www.saucedemo.com` тохиргоотойгоор ажилладаг.

## Playwright vs Selenium — ажиглалт
Үнэндээ Selenium дээр өмнө нь ажиллаж байгаагүй болохоор шууд харьцуулж чадахгүй байгаа, гэхдээ материал уншиж, хичээлийн слайдыг харахад нэг зүйл маш их анзаарагдсан — auto-wait жинхэнэ ач холбогдолтой юм байна. Эхэндээ "Products" гэдэг текстийг getByText-ээр л шалгачихлаа гээд явсан чинь webkit дээр тест унаад байсан, учир нь тэр текст өөр газар давхардаж байгаа юм билээ. Эхэндээ бодоод байхад "тестийг элемент ачаалахаас нь өмнө шалгачихсан юм болов уу" гээд wait нэмэх гэж бодсон, гэтэл харахаар асуудал нь огт өөр байсан — locator нь тодорхойгүй байсан юм. exact: true нэмэхэд шууд засарсан. Энэ дээрээс сурч авсан зүйл маань — sleep эсвэл timeout нэмэх гэж яарах хэрэггүй, эхлээд яагаад унаж байгааг нь ойлгох хэрэгтэй юм байна.

Codegen-ийг бас туршиж үзсэн. Бичихдээ ихэвчлэн ID эсвэл нарийн CSS selector руу шууд явж байна лээ, надад bootcamp дээр л биш яг зааврын PDF-д "ID хэрэглэхээс зайлсхий" гэж бичсэн байсан болохоор би тэрийг нь гараар getByRole/getByPlaceholder болгож солисон. Мөн codegen нь юу ч шалгадаггүй, зөвхөн товших, бичих гэсэн үйлдлүүдийг л бичдэг нь — expect тал дээр нь бүрэн өөрөө нэмж бичих хэрэгтэй болсон, тэгэхгүй бол тест гэхээсээ илүү бичлэг л болчихдог юм байна.

Playwright суулгах, ажиллуулах явц бол над шиг эхлээд удирдамжаа уншаад л, дараа нь бодит амьдрал дээр өөр асуудалтай тулгардаг хүмүүст маш их таалагдсан хэсэг. npx playwright install гэдэг нэг команд л хийчихээр хөтчүүд өөрсдөө татагдаад, тохиргоо хийхгүйгээр л ажиллаж эхэлсэн. Энэ талаар Selenium-ийг материалаас уншсаны хэрээр driver-ийн хувилбар зөрчилдөх, PATH тохируулах гэх мэт зүйлс нэлээд гардаг гэсэн, тэгэхээр энэ нэг л алхам их том ялгаа шиг санагдсан — гэхдээ энэ бол зөвхөн уншсанаас хэлж байгаа зүйл, өөрөө туршаагүй болохоор бат итгэлтэй хэлж чадахгүй байна.

## AI ашигласан тухай (нэмэлт даалгавар)

Тестийн код бичихдээ Claude (AI)-г ашигласан. Амжилттай нэвтрэх болон бараа сагслах тестүүдийн эхний хувилбарыг Claude-оор бичүүлсэн бөгөөд дараа нь өөрөө шалгаж, засвар оруулсан. AI-ийн гаргасан код анх бичихдээ ажиллаж байсан ч зарим локатор нь тодорхойгүй байсан — жишээ нь getByText('Products')-ийг exact: true параметргүйгээр ашигласан тул webkit дээр өөр элементтэй давхцаж, тест тогтворгүй (flaky) болж болзошгүй байсныг би засварласан. Мөн AI-ийн бичсэн код заримдаа тайлбар (comment) дутуу байсан тул би locator сонголтын шалтгааныг (яагаад XPath-аас зайлсхийсэн, яагаад CSS id биш getByRole ашигласан гэх мэт) өөрөө нэмж бичсэн.
Repo-гоо GitHub-д байршуулсны дараа AI-г бас алдаа оношлоход ашигласан — тухайлбал docs/playwright-report/ хавтас яагаад push хийгдэхгүй байгааг олж, .gitignore дотор playwright-report/ гэсэн мөр бүх зам дээр (path-аас үл хамааран) хэрэгжиж байгааг тайлбарлуулсан. Эндээс ойлгож авсан зүйл бол: AI-ийн гаргасан кодыг шүүмжгүй хуулбарлахгүй, ялангуяа assertion болон locator-ийн нарийвчлалыг өөрөө шалгаж, ойлгож ашиглах ёстой гэдгийг ойлгосон.
